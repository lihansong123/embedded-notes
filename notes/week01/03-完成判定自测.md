# 答案解析（先做完再看！）

## A 部分答案

**A1**：`p` 是 `int*`，`q` 是 `int`；`pp` 是 `char**`；第一个 `f` 是"返回 `int*` 的函数"；第二个 `f` 是"函数指针，指向返回 `int` 的函数"；`arr` 是"元素为 `int*` 的数组"；第二个 `arr` 是"指向 `int[10]` 的指针（数组指针）"。
> 考点：`[]`/`()` 优先级高于 `*`；`*p, q` 陷阱。

**A2**：`20 4`。数组名在 `sizeof` 里不退化为指针，取整个数组大小；指针永远是 4 字节。

**A3**：`6 4`，`strlen` = `5`。`s1` 是数组（5 字符 + `'\0'`），`s2` 是指针（4 字节），字符串本体在只读区。

**A4**：`4` 和 `20`。`a + 1` 是 `int*` 步长 4 字节；`&a + 1` 是 `int(*)[5]` 步长整个数组 20 字节。
> 这是区分"数组名"和"数组的地址"的最经典一题。

**A5**：**数值相同**（都是首元素地址），**类型不同**：`a` 在表达式中退化为 `int*`，`&a` 是 `int (*)[5]`。所以 `a+1` 走 4 字节，`&a+1` 走 20 字节。

**A6**：后缀 `++` 优先级高于 `*`，所以先取 `p` 的旧值 → 对该地址解引用并写 0（`*(p) = 0`）→ 然后 `p = p + 1`（步长 `sizeof(*p)`）。等价于 `{ *p = 0; p++; }`。

**A7**：`const char *p`：指向的内容不可改，`p` 本身可改（"只读指针"）。`char * const p`：`p` 不可改，指向的内容可改（"指针常量"）。
函数形参更常用 **`const char *p`**（即 `const T *`），因为要把"我不会改你传进来的数据"写进接口契约，同时保留传指针的效率。嵌入式里用于"输入型"参数，如 `void show(const cfg_t *in)`。

**A8**：
```c
void swap(int *x, int *y) { int t = *x; *x = *y; *y = t; }

int alloc_int(int **pp) {                   /* 要改 int* 本身，传 int** */
    *pp = (int*)malloc(sizeof(int));
    if (*pp == NULL) return -1;             /* 必须判空 */
    **pp = 42;
    return 0;
}
/* 调用：int *p = NULL; alloc_int(&p); */
```
原因：C 只有值传递，形参 `int *pp` 收到的是一份拷贝；如果函数形参是 `int *p`，`p = malloc(...)` 只改了副本，调用方的指针不变（且那块内存泄漏）。

**A9**：因为传进去的是"地址的拷贝"。拷贝和原变量**值相同**，都指向同一块内存，所以顺着这个地址去写，改的是同一块内存。**改的从来不是外部变量本身，而是它指向的对象。**

**A10**：`buf` 是局部数组，函数一返回栈帧回收，返回的地址悬垂。
正确写法：① `static char buf[16];`（注意不可重入、非线程安全）；② 调用方传缓冲 `void get_name(char *out, size_t n) { snprintf(out, n, "%s", "stm32"); }`（嵌入式中首选）。

**A11**：
- 野指针：指针未初始化就使用（`int *p; *p = 1;`）→ 定义即初始化 `= NULL`。
- 悬垂指针：对象已释放还在用（`free(p)` 后继续用 / 返回局部地址）→ `free` 后置 `NULL`，不返回局部地址。
- 内存泄漏：分配了但丢了地址、没有释放 → 每个 `malloc` 配一个 `free`；嵌入式优先用静态缓冲/内存池。

**A12**：`s` 指向字符串**字面量**，它放在只读区（在 MCU 上通常就是 Flash / 受保护区域）。**写只读区 → 总线错误 → HardFault。** 应该写 `char s[] = "hello";`（拷贝到栈/RAM 里再改）。

**A13**：`11 20`。`*a` 是 `a[0] = 10`，`+1` 得 11（先解引用再加）；`*(a+1)` 是 `a[1] = 20`。**对比 `*(a+1)` 与 `*a+1`，这是优先级最经典的坑。**

**A14**：等价。因为 `a[i]` 定义为 `*(a + i)`，而加法可交换 → `*(i + a)` → `i[a]`。
实际**一律写 `a[i]`**：`i[a]` 虽然合法，可读性极差，会被 code review 打回。

**A15**：因为形参里的数组会**退化为指针**（`int *arr`），`sizeof(arr)` 得到 4 而不是整个数组。
正确写法：`void f(int *arr, size_t n)`，长度单独传。

**A16**：`bad()` 会溢出。局部数组在**栈**上，MCU 栈通常只有 1~4KB（Keil 默认启动文件里 `Stack_Size` 常是 0x400 = 1KB），4KB 数组直接越界踩栈。
改成 `static uint8_t buf[4096];` → 进 `.bss`，不占栈。若还需要并发/可重入，用内存池或调用方传缓冲。

**A17**：
- `.data` 已初始化的全局/静态变量 → **占 RAM**（初值也占 Flash，启动时拷贝过来）
- `.bss` 未初始化（或初始化为 0）的全局/静态变量 → **占 RAM**，不占 Flash（启动清零）
- `.rodata` 常量、字符串字面量 → **占 Flash**
- `.text` 代码 → **占 Flash**
- 栈、堆 → **占 RAM**，运行时动态使用
> 第 10 周读 MAP 文件时就靠这张表定位 RAM 溢出。

**A18**：`0x40010C0C` 是 GPIOB_ODR 的绝对地址常量 → `(volatile uint32_t *)` 把它转成"指向 volatile 32 位无符号数"的指针 → 外层 `*` 解引用，于是这个宏可以像变量一样读/写，`|=` 就是"读—改—写"ODR 的第 0 位。
去掉 `volatile`：编译器认为"没人改这块内存"，在循环轮询寄存器（如 `while(!(RCC->CR & (1<<17)));`）时会把它优化成死循环，或把写寄存器优化掉。**外设寄存器必须 `volatile`。**

**A19**：
```c
uint16_t len = (uint16_t)(buf[2] | (buf[3] << 8));   /* ✅ 逐字节拼，不依赖对齐、大小端显式 */
uint16_t len = *(uint16_t*)&buf[2];                   /* ⚠️ 依赖对齐；Cortex-M3 支持非对齐但外设/DMA 上易出错 */
```
**第一种更安全**：不依赖缓冲区对齐、不违反严格别名规则、大小端写得明明白白。嵌入式协议解析**统一用逐字节拼接**。

**A20**：
```c
void reverse(int *a, size_t n)      /* n 是元素个数 */
{
    if (a == NULL || n < 2) return;         /* 边界：空指针、0/1 个元素直接返回 */
    int *l = a, *r = a + n - 1;
    while (l < r) {                         /* 用 l < r，不是 <=，否则中间元素自己换一次（虽无害但慢） */
        int t = *l; *l = *r; *r = t;
        l++; r--;
    }
}
```
边界三看：`n == 0`（`a + n - 1` 会下溢成 `a - 1`，非法）、`n == 1`、`a == NULL`。

## B 部分答案

**B1**：参考答案见 `02-STM32-时钟树RCC与GPIO八种模式.md` 的**第 7 节（白板默写模板）** 与 `../STM32F1_clock_tree.png`。要点：HSI 8M / HSE 8M / LSI 40k / LSE 32.768k；HSE×9=72M → SYSCLK 72M → HCLK 72M；PCLK1 36M、PCLK2 72M；USB 48M（PLL/1.5）、ADC 12M（PCLK2/6）；Flash 2WS。

**B2**：HSI 8MHz 内部 RC（±1% @25°C，兜底/备用源，可作 PLL 源的一半即 HSI/2 = 4MHz）；HSE 4~16MHz 外部晶振（通常 8MHz，高精度，主时钟源）；LSI ≈40kHz 内部 RC（IWDG 独立看门狗、RTC 备用）；LSE 32.768kHz 外部晶振（RTC 走时）；PLL（输入 ×2~×16，把 HSE 8M 变 72M）。

**B3**：`SW` 是"我要选哪个源"（软件写的）；`SWS` 是"硬件实际在用哪个源"（只读回显）。
必须查 `SWS`：如果目标源没就绪，硬件会**拒绝切换**，此时 `SW` 已被你改成目标值，但 `SWS` 不变。只查 `SW` 等于自欺欺人；`SWS` 才代表真相。容错/自检代码里也用它判断是否真的跑在 PLL 上。

**B4**：`PLLMUL[3:0] = 0b0111`（= `RCC_CFGR_PLLMULL9`）。
因为它是一张**编码表**：`0000`=×2、`0001`=×3 …… `0111`=×9 …… `1110`=×16。写十进制 9（`1001`）会被解释成 ×11，主频变成 88MHz → 超频、随机死机。

**B5**：APB1 上限 **36MHz**（`PPRE1` 至少 /2）。超了：USART2/3、I2C、SPI2、CAN、USB 的时序全错，表现为通信随机失败、采样错乱，而 CPU 还在跑（最难查的一类 bug）。因为 APB1 挂的是低速外设，芯片设计规定其上限 36MHz。

**B6**：标准配 `ADCPRE = /6` → **12MHz**（上限 14MHz）。ADC 时钟超限会让采样保持时间不足，采样值偏小/跳变。

**B7**：48~72MHz 需 **2 个等待周期**（`FLASH_ACR_LATENCY_2`）；60MHz 属于该区间 → 2WS。不设：Flash 最快 24MHz 跟不上 CPU 取指，出现取指错误、跑飞、随机 HardFault。还应开**预取缓冲**（`FLASH_ACR_PRFTBE`）。

**B8**：当某条 APB 总线的预分频系数 **≠ 1** 时，该总线上的**定时器**会得到 `PCLK × 2` 的时钟。例：APB1 = 36MHz（÷2），则 TIM2~TIM7 的计数时钟是 **72MHz**。
成立条件：仅对"挂在该 APB 上的定时器"成立；且分频系数必须 ≠ 1。第 6 周算 PWM 频率时用错了会差一倍。

**B9**：

| 模式 | CNF | MODE | 4 位值 | 用途 |
|---|---|---|---|---|
| 输入浮空 | 01 | 00 | 0x4 | 外部已有上拉的按键、UART RX |
| 输入上拉 | 10 | 00 | 0x8（ODR=1） | 按键接 GND |
| 输入下拉 | 10 | 00 | 0x8（ODR=0） | 按键接 VCC |
| 模拟输入 | 00 | 00 | 0x0 | ADC 采集 |
| 推挽输出 | 00 | 11 | 0x3 | LED、普通输出 |
| 开漏输出 | 01 | 11 | 0x7 | 线与、电平转换 |
| 复用推挽 | 10 | 11 | 0xB | UART TX、PWM |
| 复用开漏 | 11 | 11 | 0xF | 硬件 I2C 的 SCL/SDA |

（MODE = `01`/`10` 分别对应 10MHz/2MHz，最常用 `11`=50MHz。）

**B10**：① `0b0011` = **0x3** ② `0b1000` = **0x8**（且 ODR 置 1）③ `0b1011` = **0xB** ④ `0b0111` = **0x7**。

**B11**：两者 `CNF=10, MODE=00`（4 位值一样），**靠 `ODR` 对应的位区分：写 1 = 上拉，写 0 = 下拉**。
PB5 上拉输入：
```c
RCC->APB2ENR |= RCC_APB2ENR_IOPBEN;      /* 先开时钟！ */
GPIOB->CRL &= ~(0xFu << (5 * 4));        /* 清 PB5 的 4 位 */
GPIOB->CRL |=  (0x8u << (5 * 4));        /* CNF=10 MODE=00 → 上拉/下拉输入 */
GPIOB->ODR |=  (1u << 5);                /* ODR=1 → 选上拉（漏了这步就变成下拉） */
```

**B12**：开漏输出级**只有下管（NMOS）**，上管永久关闭。输出"1"时管子关断，引脚处于**高阻**，电平谁都不驱动，所以必须靠**外部上拉电阻**把它拉高。
必须用开漏的场景：① I2C 的 SDA/SCL（多设备共享总线、线与，防止推挽对拉短路）；② 3.3V 器件驱动 5V 器件（上拉到 5V 做电平转换）；③ 多输出"线与"。
结构：推挽 = PMOS(上管) + NMOS(下管)，轮流导通；开漏 = 只有 NMOS + 外部上拉电阻。

**B13**：**漏了开 GPIOB 的时钟**。
```c
RCC->APB2ENR |= RCC_APB2ENR_IOPBEN;   /* ← 缺这行：CRL/ODR 写了也不生效，B 端口时钟是关的 */
```
（这是新手第 1 大坑。补充检查：如果灯是高电平亮，`ODR |= 1<<0` 是对的；如果低电平亮要写 `BRR`/`BSRR` 复位位。）

**B14**：PA13 = SWDIO、PA14 = SWCLK，是**下载/调试接口**。把它们配成普通 GPIO（尤其是输出）会导致下载器连不上、无法再烧写，严重的要靠 BOOT0 拉高进 bootloader 才能救回。
要用 PB3/PB4/PA15（默认 JTAG 的 JTDO/JNTRST/JTDI），必须先关闭 JTAG 只保留 SWD：
```c
RCC->APB2ENR |= RCC_APB2ENR_AFIOEN;
AFIO->MAPR = (AFIO->MAPR & ~(7u << 24)) | (2u << 24);   /* SWJ_CFG = 010 */
```

**B15**：用**延时闪烁自检**（无仪器时最实用）：
1. 写 `while(1) { LED 翻转; HAL_Delay(500); }`，用手机秒表量 10 次闪烁的总时长。
2. 期望：10 × 1s ≈ **10 秒**（一次亮+一次灭算 1 秒周期）。
3. 如果实际约 **90 秒** → 慢了 9 倍 → 说明其实还在跑复位默认的 **HSI 8MHz**，PLL 没切成功（查 HSE 是否起振、`SW`/`SWS`、`PLLMUL` 编码）。
4. 进一步确认：串口打印 `(RCC->CFGR >> 2) & 0x3`（应为 2 = PLL）和 `SystemCoreClock`（应为 72000000）；有条件再用 MCO 把 SYSCLK 输出到 PA8 给逻辑分析仪测。

## 白板口述验收（周日录音用）

**要求**：对着一张白纸，60 秒内讲完，不许看笔记。录音后回听，找"卡壳点"。

**时钟树口述稿**（照此结构讲）：
> 复位后默认 HSI 8MHz。为了跑 72MHz：开 HSE 8MHz 等 HSERDY；把 Flash 设成 2 个等待周期并开预取；先把总线分频设好——AHB 不分频、APB1 二分频（因为上限 36MHz）、APB2 不分频；然后配 PLL：源选 HSE、倍频 ×9；开 PLL 等 PLLRDY；最后 SW 切 PLL 并轮询 SWS 确认。结果 SYSCLK 72M、HCLK 72M、PCLK1 36M、PCLK2 72M，USB 由 PLL/1.5 得 48M，ADC 由 PCLK2/6 得 12M。

**GPIO 口述稿**：
> 每个引脚在 CRL（0~7）或 CRH（8~15）里占 4 位，高 2 位 CNF、低 2 位 MODE。MODE=00 是输入，01/10/11 是输出 10/2/50MHz。输入时 CNF 选模拟(00)、浮空(01)、上拉下拉(10)，上下拉由 ODR 决定；输出时 CNF 选推挽(00)、开漏(01)、复用推挽(10)、复用开漏(11)。开漏只能拉低、高电平靠外部上拉，I2C 和电平转换必须用它。用之前必须先开对应 GPIO 的 APB2 时钟。
