# C 语言精讲 01：指针与内存模型

> 第 1 周主线之一。读完必须能回答一个问题：**"指针到底是什么？"** —— 答案不是"指向变量的变量"这种背诵，而是：**指针是一个存放地址的整数，它的类型只决定两件事：解引用时取几个字节、加减 1 时跳几个字节。**
>
> 阅读方式：每读完一节，立刻打开 `code/pointer_drills.c` 做对应题，不要连读。第 13 节是动手清单。

## 1. 先建立四个心智模型（本节最重要）

如果你只记住这一节，后面全部是它的推论。

### 模型①：内存 = 一个巨大的 `unsigned char` 数组

```
地址:  0x2000_0000 0x2000_0001 0x2000_0002 0x2000_0003 ...
内容: [   0x78   ][   0x56   ][   0x34   ][   0x12   ] ...
                      ↑
        一个 4 字节变量 0x12345678（小端：低字节在低地址）
```

- **地址就是数组下标**，本质是一个整数（32 位 MCU 上是 32 位无符号数）。
- **变量 = 某段地址的别名 + 类型（决定长度和解释方式）**。
- 所谓"内存模型"，就是搞清楚"这个变量的地址落在哪一段、谁负责回收它"。

### 模型②：指针变量本身，也有地址

```c
int  a = 10;
int *p = &a;

printf("%p\n", (void*)&a);   /* a 的地址，比如 0x20000004 */
printf("%p\n", (void*)&p);   /* p 自己的地址，比如 0x20000008 —— 和 a 没关系！ */
printf("%p\n", (void*)p);    /* p 的内容，等于 &a = 0x20000004 */
printf("%d\n", *p);          /* 顺着 p 里的地址去取 4 字节 = 10 */
```

**四个量，两个地址，别混**：`&a`/`p` 是同一个值；`&p` 是另一个完全独立的位置。这是初学者 90% 困惑的根源。

### 模型③：`*` 在"声明"和"使用"里是两个不同的符号

| 出现位置 | 含义 | 例子 |
|---|---|---|
| 声明/定义里 | 类型的一部分，"这是个指针" | `int *p;` → 定义变量 `p` |
| 表达式里 | 一元运算符，"解引用/取内容" | `*p = 5;` → 往 p 指的地址写 5 |
| 表达式里 | 乘号 | 无关 |

```c
int *p, q;     /* p 是指针，q 是 int！很多人以为两个都是指针 */
int *p, *q;    /* 这才是两个指针 */
```

### 模型④：`&` 和 `*` 互逆（但只在合法对象上）

```c
&(*p) == p        /* 取"p 所指对象"的地址 = p 本身 */
*(&a) == a        /* 对 a 的地址解引用 = a */
```

⚠️ 反例：`&(*p)` 里如果 `p` 是野指针，`*p` 已经非法，别以为能靠取地址把它救回来。

## 2. 指针的声明与读法

C 的声明读法：**从变量名出发，先右后左（右左法则）。**

```c
int  *p;          /* p 是 → 指针 → 指向 int            ：整型指针 */
char **pp;        /* pp 是 → 指针 → 指针 → 指向 char    ：二级指针 */
int  *f(void);    /* f 是 → 函数 → 返回 指针 → int      ：返回指针的函数 */
int (*f)(void);   /* f 是 → 指针 → 指向 函数 → 返回 int ：函数指针（第2周重点） */
int  *arr[10];    /* arr 是 → 数组 → 元素是 指针 → int   ：指针数组 */
int (*arr)[10];   /* arr 是 → 指针 → 指向 数组 → 元素 int：数组指针（第2周） */
const char *p;    /* p 指向的内容不可改，p 可改 */
char * const p;   /* p 不可改，指向的内容可改 */
```

**记忆口诀**：`[]` 和 `()` 的优先级高于 `*`，所以 `*` 要先加括号才能"先结合变量名"。
**`const` 读法**：跳过类型名，看 `const` 紧挨着谁——紧挨 `*p` 就锁内容，紧挨 `p` 就锁指针自己。

## 3. 解引用与类型：`*p` 到底取几个字节？

**类型 = 字节数 + 解释方式。** 地址本身不带长度信息，长度全靠指针类型。

```c
unsigned int v = 0x12345678;
unsigned char *pc = (unsigned char*)&v;
unsigned int  *pi = &v;

printf("%02X\n", *pc);        /* 78  —— 只取 1 字节，小端所以是最低字节 */
printf("%02X\n", *(pc + 1));  /* 56  */
printf("%08X\n", *pi);        /* 12345678 —— 取 4 字节，整体解释 */
```

| 类型 | 步长（+1 跨多少字节） | 一次解引用读写 |
|---|---|---|
| `char*` | 1 | 1 字节 |
| `short*` | 2 | 2 字节 |
| `int*` / `float*` / `long*`（Cortex-M 上） | 4 | 4 字节 |
| `double*` | 8 | 8 字节 |
| `struct S*` | `sizeof(struct S)`（含对齐填充） | 整个结构体 |

**嵌入式实战意义**：解析协议帧时，`*(uint16_t*)&buf[2]` 这种写法字节数写错一位就是"数据永远差 256 倍"。**代替方案**：

```c
/* 危险：依赖对齐，还可能违反严格别名规则 */
uint16_t len = *(uint16_t*)&buf[2];

/* 安全：逐字节拼，顺便显式处理大小端 */
uint16_t len = (uint16_t)(buf[2] | (buf[3] << 8));   /* 小端 */
```

## 4. 多级指针：`int **` 什么时候必须用

**只有三种场景，背下来。**

### 场景 A：被调函数要**修改指针本身**（不是修改它指向的内容）

```c
/* 错误示范：值传递，改的是副本，调用方 p 不变 */
void alloc_bad(int *p) { p = (int*)malloc(sizeof(int)); }   /* 内存泄漏 + 无效 */

/* 正确：要改指针，就传指针的地址 */
void alloc_ok(int **pp) {
    *pp = (int*)malloc(sizeof(int));
    if (*pp == NULL) { /* 必须判空 */ return; }
    **pp = 42;
}

int *p = NULL;
alloc_ok(&p);      /* 传 &p，类型 int** */
printf("%d\n", *p); /* 42 */
```

**判断标准一句话**：函数要改谁，就传谁的地址。要改 `int` 就传 `int*`，要改 `int*` 就传 `int**`。

### 场景 B：指针数组 / 字符串数组（`char *argv[]` 退化为 `char **`）

```c
const char *names[] = {"led", "uart", "i2c"};   /* 指针数组 */
const char **p = names;                          /* 数组名退化为指向首元素的指针 */
printf("%s\n", p[1]);      /* uart */
printf("%c\n", *p[1]);     /* u —— 先 p[1] 取到"uart"首地址，再解引用 */
printf("%c\n", **p);       /* l —— p[0] 首字符 */
```

**`*p[1]` 和 `(*p)[1]` 完全不同**：前者是"第 2 个字符串的首字符"，后者是"第 1 个字符串的第 2 个字符"。`[]` 优先级高于 `*`。

### 场景 C：二维数组传参 / 输出型参数（驱动注册表、缓冲区返回）

```c
/* 把一整块缓冲区交出去，同时回传长度 */
int read_frame(uint8_t **out, size_t *out_len) {
    static uint8_t buf[64];
    *out = buf;            /* 让调用方拿到地址 */
    *out_len = 8;
    return 0;
}
```

## 5. 指针运算：加减的是"元素个数"，不是字节

```c
int a[5] = {0};
int *p = a;
int *q = &a[3];

printf("%d\n", (int)((char*)(q) - (char*)(p)));  /* 12 字节 */
printf("%d\n", (int)(q - p));                    /* 3  —— 指针相减得到"元素个数"，类型 ptrdiff_t */
printf("%p\n", (void*)(p + 1));                  /* 比 p 大 4 —— int* 步长 4 */
```

**规则**

| 运算 | 合法性 | 结果 |
|---|---|---|
| `p + n` / `p - n` | 结果必须落在**同一数组内或刚好末尾后一位** | 否则是未定义行为（UB） |
| `p - q` | 两者必须指向同一数组 | 元素个数 |
| `p1 > p2` 比较 | 推荐仅同数组内比较 | 跨对象比较不可移植 |
| `p * 2`、`p + q` | **非法** | 编译报错 |

**梯形陷阱**：

```c
int a[5] = {0};
int *p = a;
if (p + 5 == NULL) { }   /* 错！越界指针不能和 NULL 比 */
while (p < a + 5) { *p++ = 0; }   /* 对：p 指针自己往后走，a 不动 */
```

**`*p++` 拆解**（后缀 `++` 优先级更高，但先返回旧值）：

```c
*p++ = 0;    /* 等价于 *(p++) = 0; 先写 p 指的字节，再让 p 走一步 */
(*p)++;      /* 把 p 指的内容加 1 */
*++p = 0;    /* p 先走一步，再写 */
```

## 6. 指针与数组：名字相同，类型不同

```c
int a[5];
int *p = a;      /* 等价于 &a[0] */

/* 数值相同 */
printf("%p %p %p\n", (void*)a, (void*)&a[0], (void*)&a);   /* 三个地址一样！ */

/* 类型/步长不同 */
sizeof(a)    == 20;    /* 整个数组 */
sizeof(p)    == 4;     /* 指针本身 */
sizeof(&a)   == 4;     /* 指针本身 */
a + 1        → 跨 4 字节（指向第 2 个元素）
&a + 1       → 跨 20 字节（跳过整个数组！）
```

**两个必须背下来的差异**

| 表达式 | 含义 | 类型 |
|---|---|---|
| `a` | 首元素地址（**数组名退化为指针**） | `int *` |
| `&a` | 整个数组的地址 | `int (*)[5]` |
| `a[i]` | 等价 `*(a + i)`，也等价 `*(p + i)`、`p[i]` | `int` |
| `sizeof(a)` | 20 | `size_t` |
| `sizeof(a)/sizeof(a[0])` | 元素个数（**数组作用域内才有效**） | `size_t` |

⚠️ **数组名不是"常量指针"，它是数组类型**，只是大多数表达式里退化为指针。两个直接后果：

1. **数组不能赋值**：`int b[5]; b = a;` 编译错误。
2. **函数形参里的数组其实就是指针**，`sizeof` 拿不到真实长度：

```c
void f(int arr[5]) {           /* 看着像数组，实际形参是 int *arr */
    printf("%zu\n", sizeof(arr));   /* 输出 4，不是 20！ */
}
void f(int *arr, size_t n) { } /* 正确写法：长度单独传 */
```

**数组指针（第 2 周预告，这里先看一眼）**：

```c
int a[3][4];
int (*p)[4] = a;       /* p 一次跳一行 */
p[1][2] == a[1][2];
```

## 7. 野指针 / 悬垂指针 / 内存泄漏

三个词的区别，一句话记住：**野指针原地没牵绳（没初始化），悬垂指针绳子还在但狗死了（对象已释放），内存泄漏狗跑了绳还牵着（丢了地址）。**

### 成因与对策

| 问题 | 典型代码 | 对策 |
|---|---|---|
| **野指针** | `int *p; *p = 1;`（p 里是随机栈值） | 定义即初始化：`int *p = NULL;` |
| **悬垂指针** | `free(p);` 后继续 `*p`，或返回局部数组地址 | `free(p); p = NULL;`；**绝不返回局部变量地址** |
| **内存泄漏** | `p = malloc(...); p = malloc(...);` 第一个地址丢了 | 每个 `malloc` 都配一个 `free`；嵌入式里优先用**静态缓冲/内存池**，少用动态分配 |
| **越界写** | `int a[3]; a[3] = 1;`（"差一"错误） | 循环用 `< n` 而不是 `<= n`；`strcpy` 换 `strncpy`/`snprintf` |

### 函数里最常见的悬垂/无效返回

```c
/* 错：返回局部数组地址，函数一返回栈帧就失效 */
char* bad(void) { char buf[16]; strcpy(buf, "hi"); return buf; }

/* 错：返回局部变量地址 */
int* bad2(void) { int x = 1; return &x; }

/* 对：static（注意不可重入/非线程安全） */
char* ok(void) { static char buf[16]; strcpy(buf, "hi"); return buf; }

/* 对：调用方给缓冲，函数只填 —— 嵌入式中最常用 */
void ok2(char *out, size_t n) { snprintf(out, n, "%s", "hi"); }
```

### 三条铁律（写在笔记第一页）

1. **定义指针就初始化**（不知道指向谁就 `= NULL`）。
2. **`free` 之后立刻置 `NULL`**（并且 `free(NULL)` 是安全的）。
3. **用之前判 `NULL`**，尤其是"分配过内存"和"别人传给我的指针"。

```c
int *p = (int*)malloc(sizeof(int) * 16);
if (p == NULL) { /* 嵌入式里要按错误处理，别默默继续 */ return -1; }
/* ... */
free(p);
p = NULL;
```

## 8. 函数传参的本质：值传递（第 4 节场景 A 的原理）

**C 只有值传递。** 形参是实参的一份**拷贝**。指针参数能改到外面的东西，是因为"拷贝了一份地址，顺着地址改到了同一块内存"——**不是**因为"传了引用"。

```c
void swap_wrong(int x, int y) { int t = x; x = y; y = t; }   /* 无效 */
void swap_ok(int *x, int *y)   { int t = *x; *x = *y; *y = t; } /* 有效 */

int a = 1, b = 2;
swap_ok(&a, &b);     /* a=2 b=1 */
```

**三档对照表（务必自己画一遍）**

| 目的 | 形参 | 调用 | 函数体写法 |
|---|---|---|---|
| 只读，不改 | `int v` 或 `const int *v` | `f(a)` / `f(&a)` | 直接用 |
| 改**指向的内容** | `int *p` | `f(&a)` | `*p = ...` |
| 改**指针本身** | `int **pp` | `f(&p)` | `*pp = ...` |

```c
/* 结构体：小结构体传值、大结构体传指针（嵌入式栈很小，默认传指针） */
void cfg_read(cfg_t *out) { out->baud = 115200; }
void cfg_show(const cfg_t *in) { printf("%u\n", in->baud); }  /* const 表示"我不改你的" */
```

## 9. 字符串：`char s[]` 和 `char *s` 不是一回事

```c
char  s1[] = "hello";   /* 栈上一个 6 字节数组（含 '\0'），可读可写 */
char *s2   = "hello";   /* s2 是栈上指针，指向【只读常量区】的 "hello" */

s1[0] = 'H';   /* 对，改的是自己的数组 */
s2[0] = 'H';   /* ❌ 未定义行为！常见现象：HardFault（嵌入式上一写就死） */
```

| | `char s[]` | `char *s` |
|---|---|---|
| 存储位置 | 栈（或静态区） | 指针在栈，字符在只读区 |
| `sizeof` | 6 | 4 |
| 可修改 | ✅ | ❌ |
| 可整体赋值 | ❌（`s = "x"` 报错） | ✅（`s = "x"` 重新指向） |

**常用函数与安全边界**

```c
strlen(s)                  /* 遇到 '\0' 停，不含 '\0'；s 无 '\0' 会一直跑 */
strcpy / strncpy           /* strcpy 不检查长度 → 溢出；strncpy 可能不补 '\0' */
strcmp                     /* 返回 0 表示相等 */
sprintf / snprintf(buf, n, ...)   /* 一律用 snprintf，别用 sprintf */
memcpy / memmove / memset  /* 内存块操作，memcpy 不支持重叠区，重叠用 memmove */
```

**嵌入式提醒**：`printf("%s", ...)` 会按 `'\0'` 一直读下去，串口缓冲区里少了结束符就会打出乱七八糟的东西——第 5 周做串口协议帧时会再遇到。

## 10. 内存四区（本节是第 10 周 MAP 文件分析的地基）

```
高地址  ┌──────────────────────────┐
        │  栈 stack（向下生长）      │  局部变量、函数形参、返回地址
        │      ↓                   │  自动回收；嵌入式里通常 1~4KB，极易溢出
        ├──────────────────────────┤
        │      ↑                   │
        │  堆 heap（向上生长）       │  malloc/calloc/realloc/free
        │                          │  手动回收；嵌入式里少用、慎用
        ├──────────────────────────┤
        │  .bss 未初始化全局/静态    │  启动代码清零
        ├──────────────────────────┤
        │  .data 已初始化全局/静态   │  启动代码从 Flash 拷初值到 RAM
        ├──────────────────────────┤
        │  .rodata 常量区           │  字符串字面量、"hello"、"abc"
        ├──────────────────────────┤
        │  .text 代码区（Flash）     │  函数机器码、中断向量表
低地址  └──────────────────────────┘
```

**验证代码（`code/memory_layout.c` 已写好，直接跑）**

```c
#include <stdio.h>
#include <stdlib.h>

int         g_init   = 42;          /* .data  */
int         g_uninit;               /* .bss   */
const int   g_const  = 7;           /* 通常 .rodata / Flash */

int main(void) {
    int          local = 1;          /* 栈  */
    static int   s_init = 2;         /* .data */
    static int   s_uninit;           /* .bss  */
    char        *heap = malloc(16);  /* 堆  */
    char        *lit  = "hello";     /* 指针在栈，'h' 在 .rodata */

    printf("g_init   = %p\n", (void*)&g_init);
    printf("g_uninit = %p\n", (void*)&g_uninit);
    printf("g_const  = %p\n", (void*)&g_const);
    printf("s_init   = %p\n", (void*)&s_init);
    printf("s_uninit = %p\n", (void*)&s_uninit);
    printf("safealoca = %p\n", (void*)heap);
    printf("local    = %p\n", (void*)&local);
    printf("lit(str) = %p\n", (void*)lit);
    free(heap);
    return 0;
}
```

> 在 PC 上跑，你会看到：`g_init/g_uninit/s_*` 地址相近（数据段）、`heap` 在中间、`local` 在最上面、`lit` 指向的字符串在最低的只读区。**在 MCU 上跑不了 printf 也没关系**——这四区的概念直接对应第 10 周的 MAP 文件：`.data` 和 `.bss` 占 RAM，`.text`+`.rodata` 占 Flash。

**三个必须能答的问题**

1. 为什么全局变量不初始化反而是"清 0"？（→ `.bss` 由启动代码 `__main` 阶段的 `__rt_entry`/`scatter` 清零，不占 Flash 空间）
2. 局部变量不初始化是什么？（→ **垃圾值**，栈上残留）
3. 为什么大数组要加 `static`？（→ 不加就进栈，几 KB 数组直接栈溢出 HardFault）

```c
void f(void) {
    uint8_t buf[4096];       /* ❌ 栈只有 1KB 时必死 */
    static uint8_t buf2[4096];/* ✅ 进 .bss，不占栈 */
}
```

## 11. 嵌入式中指针的特殊用法（提前种下三颗种子）

### ① 用指针直接访问寄存器

```c
#define GPIOB_ODR  (*(volatile uint32_t *)0x40010C0C)
GPIOB_ODR |= (1u << 0);       /* 点亮 PB0 */
```

拆开读：`0x40010C0C` 是地址常量 → `(volatile uint32_t *)` 转成"指向 volatile 32 位整数"的指针 → `*` 解引用 → 这就是一个"变量"，可以读可以写。

**为什么必须是 `volatile`**：告诉编译器"这块内存可能被硬件改变，别优化掉、别缓存到寄存器里"。裸写 `while(!(RCC->CR & (1u<<17)));` 如果没有 volatile，优化后就是死循环。**第 3 周展开。**

### ② 函数指针 = 回调（第 2 周展开）

`HAL_GPIO_EXTI_Callback`、`FreeRTOS` 任务入口、驱动注册表都靠它。

### ③ 对齐

- Cortex-M3/M4 **支持**非对齐访问（`*(uint32_t*)(buf+1)` 能跑），但**外设寄存器、DMA 缓冲区、`__packed` 结构体**上极易出问题。
- 习惯：**协议缓冲区解析用逐字节拼接**（见第 3 节），结构体通信时确认两边对齐一致（第 2 周讲 `#pragma pack`）。

## 12. 八个经典坑（每个都对应一道自测题）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | `int *p, q;` 以为两个都是指针 | 写成 `int *p, *q;` |
| 2 | `char *s = "hi"; s[0]='H';` | 用 `char s[] = "hi";` |
| 3 | 函数里 `arr` 用 `sizeof(arr)/sizeof(arr[0])` | 长度当参数传进来 |
| 4 | `free(p)` 后再用 p，又 `free(p)` 一次 | 置 `NULL`，`free(NULL)` 安全 |
| 5 | `p = malloc(...)` 不判空 | 一律判 `NULL`，尤其嵌入式 |
| 6 | `a[i]` 与 `i[a]` 搞混 | 两者**等价**（`*(a+i)`），但别这么写 |
| 7 | 返回局部变量/局部数组地址 | 用 `static` 或让调用方传缓冲 |
| 8 | 想让函数改指针，只传了 `int*` | 传 `int**` |

## 一句话总结（贴在显示器上）

> **地址是下标，变量是别名，指针是装下标的整数，类型只决定"取几字节、走几步"。**
> **要改谁就传谁的地址；分配了就要释放，释放了就要置空。**
